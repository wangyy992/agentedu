# AI 出题 / 自适应辅导 Agent

把一段学习材料(讲义、文章、PDF)丢进去,Agent 会自己完成一整条教学闭环:

```
理解材料 → 建知识图谱 → 规划学习路径 → 讲解 → 出题 → 判分 → 按掌握情况调整下一步
```

不是"套壳问答"。判断一个项目算不算真 agent,看四件事:**多步骤、有状态、能检索、能自适应**。
这四点在本项目里分别落在:显式状态机(`agent/orchestrator.py`)、贝叶斯知识追踪
(`agent/policy.py`)、BM25 检索 + 引用核验(`retrieval/`、`agent/qa.py`)、
以及由掌握度反向驱动的出题难度与补救策略。

```
┌──────────┐   ┌───────────┐   ┌──────────┐
│ 材料      │──▶│ 切块 + BM25│──▶│ 知识图谱  │  概念、先修依赖、证据片段
│ md/pdf/…  │   │ 索引       │   │ (LLM 抽取)│
└──────────┘   └───────────┘   └────┬─────┘
                                     │ 拓扑排序(纯代码,不交给模型)
                                     ▼
                              ┌─────────────┐
                              │ 学习路径     │
                              └──────┬──────┘
                                     ▼
   ┌──────────────────── 有状态主循环 ─────────────────────┐
   │                                                       │
   │   ┌──────────┐  决策(纯函数)   ┌──────────────────┐  │
   │   │ 策略层    │─────────────────▶│ 讲解 / 出题 / 补救 │  │
   │   │ BKT 掌握度│                  │ 判分(LLM + RAG)  │  │
   │   └────▲─────┘                  └─────────┬────────┘  │
   │        │      得分、误区标签                │           │
   │        └──────────────────────────────────┘           │
   └───────────────────────┬───────────────────────────────┘
                           ▼
              SQLite:会话状态 · 作答流水 · 错题本 · 误区统计
```

学生可以随时打断提问,由一个**真正的 tool-use 循环**处理:模型自己决定检索什么、
检索几次、要不要查这个学生的掌握状态,最后给出带引用的回答,引用还会被逐条核验。

## 30 秒跑起来(无需 API Key)

项目内置一个**离线假模型**,用确定性规则产出各步骤的结构化输出。它不模拟模型的
"智能",只保证接口与数据结构一致——所以编排、状态机、自适应策略这些真正的工程
逻辑可以完全离线跑通和测试(CI 用的就是它)。

```bash
# 一键配置(建虚拟环境、装依赖、引导填 API Key、自检)
bash scripts/setup.sh
source .venv/bin/activate

# 或者手动来
python -m venv .venv && source .venv/bin/activate
pip install -e .

# 看 agent 怎么读懂材料、怎么排学习路径
python -m tutor.cli --fake ingest gradient_descent

# 交互式辅导(输入 :? 加问题可随时提问,:q 退出)
python -m tutor.cli --fake tutor gradient_descent

# 网页界面
python -m tutor.cli --fake serve      # → http://127.0.0.1:8000
```

接真实模型只要去掉 `--fake` 并配好 Key。两种方式,任选其一:

```bash
# 方式一:复制模板改一下(推荐,.env 已在 .gitignore 里,不会被提交)
cp .env.example .env
#   编辑 .env,填入 ANTHROPIC_API_KEY=sk-ant-...

# 方式二:直接设环境变量(临时,关掉终端就没了)
export ANTHROPIC_API_KEY=sk-ant-...

python -m tutor.cli tutor gradient_descent
```

真实环境变量优先于 `.env`,所以 Docker / CI 里传进来的值不会被文件覆盖。
**永远不要把 key 写进代码或提交进 git** —— 一旦推上 GitHub,即使事后删掉,
它仍然留在提交历史里,必须去供应商后台吊销重发。

## 六个设计决策(以及为什么这么选)

### 1. 决策与生成分离 —— 教学顺序不能被模型的抖动左右

`policy.decide()` 是一个**不调用 LLM 的纯函数**,它看当前状态,输出"下一步做什么":

| 动作 | 触发条件 |
|---|---|
| `TEACH` | 当前概念还没讲过 |
| `PRACTICE` | 已讲过、未达标,出一道匹配难度的题 |
| `REMEDIATE` | 掌握度低 **且** 同一个误区出现 ≥2 次 → 换角度重讲 + 降难度追问 |
| `REVIEW` | 某概念掌握后过了 N 步 → 间隔复习防遗忘 |
| `ADVANCE` | 达标,或练满次数上限(防止卡死) |

每个决策都带 `reason` 字段,一路透传到 CLI 和网页上。任何一道题都能回答
"为什么是现在给你出这一道"——这是教育产品必须能解释的东西,也是纯 prompt 方案给不了的。

### 2. 掌握度用 BKT 建模,并修掉了它的一个经典坑

标准贝叶斯知识追踪只接受 0/1,而这里的判分是 `[0,1]` 连续分,所以在"全对后验"和
"全错后验"之间按分数插值。

关键的一处修正在学习增益项上。常见写法给一个恒正的增益(比如 `p_transit * (0.4 + 0.6*score)`),
结果是**一个长期只拿半分的学生会被慢慢推过掌握阈值**。本项目改成 `p_transit * max(0, (score-0.5)*2)`:
半分及以下不给增益,纯贝叶斯更新收敛到 ~0.42 的不动点,永远不会误判掌握。
这个 bug 是评测里的校准误差指标暴露出来的,不是靠肉眼看出来的
(见 `tests/test_policy.py::test_persistent_half_credit_never_reaches_mastery`)。

### 3. "掌握"需要证据,不只是概率

只看 BKT 概率是不够的——连对两道难度 1 的题也能把 `p_known` 顶到 0.9,但那只证明
学生背下了定义。所以达标要同时满足三条:

- 掌握概率 ≥ 0.85
- 至少做够 3 题
- **在难度 ≥3(应用层级)上答对过**,且这个要求以概念自身难度为上限

### 4. 拓扑排序交给代码,依赖关系才交给模型

模型负责判断"不懂 A 就学不会 B"(它擅长),代码负责把图变成一条稳定序列(它必须正确)。
排序结果确定可复现,同层由易到难,遇到循环依赖会挑难度最低的节点破环并如实记录到
`cycles_broken`,而不是崩掉或悄悄丢概念。

### 5. 一切可溯源

- 每道题绑定 `source_chunk_ids`,概念抽取阶段模型编造的片段编号会被直接剔除;
- 讲解和判分都要求逐点标注 `[c0xx]`;
- 答疑环节回答完还会做一次**引用核验**:模型声称的编号如果没出现在真实检索结果里,
  会被标记出来而不是照单全收。

### 6. Prompt caching 的布局是设计出来的,不是加个参数

请求前缀顺序是 `tools → system → messages`,任何一个字节变化都会让后面的缓存全部失效。
所以:

```python
system = [
    {"type": "text", "text": 全局固定的 system},
    {"type": "text", "text": 材料全文, "cache_control": {"type": "ephemeral", "ttl": "1h"}},
    {"type": "text", "text": 本次任务的指令},   # ← 易变内容必须排在缓存断点之后
]
```

一次辅导会话对同一份材料要调用几十次模型,材料全文只在第一次付全价。
这个布局有测试锁死(`tests/test_llm.py::test_material_sits_behind_cache_breakpoint_and_task_prompt_after_it`)。

**顺带一提**:选择题答对时判分**完全不调用模型**——规则判定 + 复用出题时生成的
`rationale`,零 token。只有答错和简答题才走 LLM 判分。

## 用模拟学生做评测

自适应教学的效果没法靠"看几个例子"下结论。`tutor.evaluation.simulate` 用 IRT
(项目反应理论)构造可控的模拟学生:

```
P(答对) = c + (1-c) · sigmoid(1.7 · (θ - b))
```

θ 是学生在该知识点上的真实能力(会随讲解和练习真的增长),b 是题目难度,c 是猜对概率。

```bash
python -m tutor.cli --fake eval gradient_descent --ability 0.3
```

跑一组不同能力的学生(离线模型,5 个知识点):

| 学生真实能力 | 总步数 | 出题数 | 难度落在甜区 | 掌握度校准 MAE |
|---|---|---|---|---|
| 0.20(弱) | 32 | 27 | 74% | 0.37 |
| 0.40 | 31 | 26 | 69% | 0.32 |
| 0.60 | 25 | 20 | 55% | 0.19 |
| 0.85(强) | 25 | 20 | 50% | 0.06 |

弱学生拿到了 35% 更多的练习量,并且更多题落在"预期答对率 0.5~0.85"的甜区
(太简单是浪费,太难是打击信心)——这就是自适应在数据上的样子。
先修顺序合规率在所有配置下都是 100%。

> **口径说明**:上表跑的是离线假模型。它的判分器按关键词命中率给分,比真实模型宽松,
> 所以弱学生那一档的校准误差偏大(agent 高估了学生)。这个数字衡量的是**编排链路**,
> 不是教学质量;要评教学质量得接真实模型跑。把这点写清楚比给一个好看的数字更重要。

## 部署

已经准备好 `Dockerfile`、`render.yaml`、`fly.toml`。**公网部署前必须开演示模式**:

```bash
docker build -t agentedu .
docker run -p 8000:8000 \
  -e ANTHROPIC_API_KEY=sk-ant-... \
  -e TUTOR_DEMO_MODE=1 \
  -e TUTOR_DAILY_LLM_CALL_BUDGET=800 \
  -v tutor_data:/data \
  agentedu
```

Render:仓库连上后自动读 `render.yaml`,只需在控制台填 `ANTHROPIC_API_KEY`。
Fly.io:`fly launch --no-deploy` → `fly secrets set ANTHROPIC_API_KEY=...` →
`fly volumes create tutor_data --size 1` → `fly deploy`。

### 护栏(`guardrails.py`)

一个会调用付费模型的公开端点,不设上限等于把钱包挂在网上。四层防护:

| 环境变量 | 默认 | 作用 |
|---|---|---|
| `TUTOR_DEMO_MODE` | 关(Docker 内为开) | **禁用按服务器路径读材料**。见下方安全说明 |
| `TUTOR_MAX_MATERIAL_CHARS` | 20000 | 材料长度直接决定每次调用的 token 数,必须封顶 |
| `TUTOR_RATE_LIMIT_PER_MIN` | 60 | 按 IP 滑动窗口。一次教学循环 = `/next` + `/answer` 两个请求,人类手速远到不了,但足以挡脚本 |
| `TUTOR_INGESTS_PER_HOUR` | 5 | 「导入新材料」单独卡死——它最贵(要读全文建知识图谱) |
| `TUTOR_DAILY_LLM_CALL_BUDGET` | 0(不限) | 全局每日调用上限。**超额后自动降级到离线模型继续服务,而不是返回 500** |

最后一条是有意的产品决策:演示站宁可内容质量下降,也不要看起来挂了。
前端会显示「今日额度已用完,已降级」的提示,流程照常走完。

### 一个必须说明的安全修复

部署这一步做之前,`POST /api/materials {"path": "/etc/passwd"}` 会让服务端读取
**任意文件**并把内容回显出来——未授权任意文件读取。本地 CLI 用没问题(是你自己的机器),
公网部署就是漏洞。现在:

- 演示模式下 HTTP 接口**完全不接受** `path`,只接受粘贴文本和内置示例名;
- 非演示模式可用 `TUTOR_MATERIAL_ROOT` 指定白名单目录,先 `resolve()` 再比对,
  挡住 `../` 穿越和符号链接;
- 内置示例名不允许包含路径分隔符。

回归用例在 `tests/test_guardrails.py`。

### 运维注意

- **必须单 worker**(Dockerfile 里写死了)。SQLite 多进程并发写会锁竞争,
  课程索引也是进程内缓存。要横向扩容得先把存储换成 Postgres。
- **挂持久卷到 `/data`**,否则容器重启会丢掉所有会话进度。
- Fly 配置里 `min_machines_running = 0`,没人访问时自动停机省钱。

> Dockerfile 本身没能在开发环境里构建验证(沙箱内没有 docker daemon)。
> 但等价路径——非编辑模式 `pip install .` 后从无关目录启动——已验证通过:
> 网页正常返回、内置示例可导入、演示模式正确拒绝路径读取、教学循环正常跑。

## 目录结构

```
src/tutor/
├── config.py              模型 ID、策略参数(集中放,方便做消融实验)
├── schemas.py             全流程数据结构 + pydantic → 严格 JSON Schema 转换
├── llm.py                 ★ 结构化输出 / 缓存布局 / tool-use 循环 / 离线假模型
├── service.py             应用层门面(CLI 与 API 共用)
├── ingest/                材料加载(md/txt/html/pdf)与按结构切块
├── retrieval/bm25.py      零依赖 BM25,中文用「字符 bigram + 英文词」混合分词
├── agent/
│   ├── comprehend.py      ① 理解材料 → 知识图谱(唯一一次读全文,进缓存)
│   ├── planner.py         ② 拓扑排序 → 学习路径(纯代码)
│   ├── explainer.py       ③ 讲解 / 针对误区的补救讲解
│   ├── item_writer.py     ④ 出题(难度对齐 Bloom 层级,绑定来源片段)
│   ├── grader.py          ⑤ 判分(规则快路径 + LLM 按 rubric 判 + 误区标签)
│   ├── policy.py          ★ 自适应策略:BKT、难度选择、复习调度(无 LLM,纯函数)
│   ├── qa.py              答疑(tool-use 循环 + 引用核验)
│   ├── tools.py           工具定义:search_material / get_student_progress
│   └── orchestrator.py    ★ 主循环状态机
├── memory/store.py        SQLite:会话快照 + 作答流水 + 错题本 + 跨会话误区统计
├── evaluation/simulate.py IRT 模拟学生 + 评测指标
├── guardrails.py          ★ 公网部署护栏:限流、每日预算、材料长度、路径白名单
├── cli.py                 命令行
├── api.py                 FastAPI + 静态页面
├── web/index.html         单文件网页界面(无构建步骤,随包分发)
└── examples/              内置示例材料(随包分发,`pip install .` 后仍可用)
Dockerfile, render.yaml, fly.toml   部署配置
tests/                     96 个测试,全部离线运行
```

为什么检索用 BM25 而不是向量库:语料是**单份材料**(几十到几百个 chunk),BM25 召回
足够;不引入 embedding 服务 = 少一个 Key、少一层部署、结果可复现。接口留成
`Retriever` 协议,要换向量检索只需实现同样的 `search()`。

## HTTP 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| `POST` | `/api/materials` | 导入材料 → 知识图谱 + 学习路径。接受 `text`(粘贴)或 `example`(内置示例名);`path` 仅非演示模式且在白名单目录内可用。按内容哈希去重 |
| `POST` | `/api/sessions` | 开始一次辅导 |
| `GET` | `/api/sessions/{id}/next` | 取下一步(讲解或一道题),带决策理由 |
| `POST` | `/api/sessions/{id}/answer` | 提交作答 → 判分 + 掌握度更新 |
| `POST` | `/api/sessions/{id}/ask` | 随时提问(tool-use + 引用核验) |
| `GET` | `/api/sessions/{id}/report` | 结课报告 + 错题本 |
| `GET` | `/api/sessions/{id}/state` | **调试用**:把 agent 内部状态整个吐出来,可以直接观察自适应是怎么决策的 |
| `GET` | `/api/health` | 健康检查 + 当前生效的限额、今日预算用量、可用的内置示例 |

超过限流返回 `429` 并带 `Retry-After` 头;材料过长 / 非法路径返回 `400`。

状态全在服务端(SQLite),前端只持有 `session_id`,刷新页面不丢进度。

## 测试

```bash
pytest            # 96 passed,全程离线,不需要 API Key
```

覆盖的关键性质:

- **策略层**:BKT 单调性与边界、长期半分不能达到掌握、复习次数上限(没有它,
  "复习失败→打回→重新掌握→又排复习"会形成永不终止的循环)、练满次数强制推进;
- **规划器**:先修优先、破环、悬空依赖不锁死、结果确定性;
- **LLM 层**:用桩 client 测**真实的** `AnthropicLLM` —— 缓存块位置、JSON 校验失败后的
  修复重试、tool 循环回灌、工具异常不被吞掉、达到轮数上限能收口;
- **端到端**:全对 / 全错都能终止、弱学生拿到更多练习、讲解先于考查、先修顺序不被违反、
  题目引用的片段真实存在、全错时报告不撒谎;
- **部署护栏**:任意文件读取被拒(回归用例)、`../` 穿越被挡、限流返回 429 带
  `Retry-After`、预算耗尽时降级而非报错。

## 已知局限

- **离线假模型不代表教学质量**。它只保证结构正确,判分宽松。上面的评测表衡量的是链路,不是效果。
- **BKT 参数是固定先验**(`p_slip=0.1`、`p_guess=0.2` 等),没有从真实数据拟合。
  有了足够的作答流水(`attempts` 表就是为此准备的)应该改成按知识点估计。
- **误区标签靠 prompt 约束规范化**,还是可能碎成一次性字符串。生产环境应该做一层
  标签归一(聚类或固定标签集)。
- **单份材料**。跨材料的知识图谱合并、长期记忆(跨会话的学生画像)尚未实现。
- 真实模型的请求体结构已对照 SDK 的类型定义验证(`output_config.format`、
  `thinking.adaptive`、`cache_control.ttl`),但本仓库的开发环境没有 API Key,
  未跑过真实推理返回的端到端质量评估。
- **单实例架构**。限流计数器和每日预算都在进程内存里,多实例部署会各算各的;
  SQLite 也不支持多机共享写。要扩容需要把前者换 Redis、后者换 Postgres。
